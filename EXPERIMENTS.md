## 1. Protocol

* **Temporal slices** (fractions of the time span): train 0–50%, early stopping 50–60%, calibration + fusion 60–67%,
  threshold selection 67–75%, **untouched test 75–100%**. For the 60-day data: days 0–30 / 30–36 / 36–40 / 40–45 / 45–60.
* Models never see the test slice. Thresholds are chosen on the threshold slice only. Baselines use the same slices.
* **Datasets:** `v1` = original synthetic data (kept as the baseline dataset); `v2` = harder synthetic data built after
  the audit (fraud in every category, fresh attacker devices, mules with genuine activity, new customers, 7 patterns);
  `v2 seed 11` = the same generator with a different seed, **used once, after the design was frozen**, as confirmation.
* **Costs:** a missed fraud costs its amount; a false alarm costs ₹100.
* **Label delay:** confirmed-fraud graph features only see labels 3 days after the payment.

### Design iteration (honest record)
The first version (one graph detector, no merchant behaviour profile) reached a mean hybrid recall of 58%. Diagnosis: no feature described merchant behaviour, and one combined graph detector diluted device signals; the fusion layer (fitted on known fraud) down-weighted anomaly evidence. Changes: merchant behaviour profile, one novelty detector per entity type, and REVIEW when fused risk OR the supervised model OR any tripwire fires. Because these changes were made after looking at test results, the seed-11 confirmation below is the unbiased check.

## 12. Latency
20,000 payments scored one at a time (x86_64, Python 3.13.18, single thread): p50 0.457 ms, p95 0.724 ms, p99 3.208 ms; ~1,847 payments/s per core. Stage means: features 80 µs, anomaly 233 µs, model_fusion 152 µs, explain 69 µs.

## 13. Not done, and why
* **GNNs (GraphSAGE / GAT):** not implemented. The graph signal is already captured online by payee, device, money-flow and confirmed-fraud graph features (payee graph is the most valuable group in the ablation), and a GNN would need batch embedding refreshes and a ~700 MB PyTorch dependency without a demonstrated gain. Next step if real data shows multi-hop structure the features miss.
* **Public datasets:** adapters for PaySim and IEEE-CIS are implemented and tested on files in their exact formats, but Kaggle is not reachable from the build environment, so no public-data results are reported.
* **Kafka and PostgreSQL:** code paths exist; no broker or database server was available, so the tested path is the in-process bus with SQLite.
